## The Core Content Strategy: Hub and Spoke

CPM does not publish original content to social platforms. CPM publishes original content to **its own website first**, then distributes adapted versions outward to each platform.

```
CPM Website (cpm.yourdomain.com/blog)
  — canonical source of all content
  — full SEO value stays on your domain
  — permanent public URL for Medium import workaround
  — the "original" that all other posts link back to
      │
      ├── Dev.to (API automated, adapted for dev audience)
      ├── Hashnode (API automated, mapped to your domain)
      ├── LinkedIn (API automated, professional angle)
      ├── Instagram (API automated, visual card format)
      ├── Product Hunt (API automated, launch day only)
      │
      ├── Hacker News (manual copy-paste, Show HN format)
      ├── Reddit (manual copy-paste, per-subreddit adaptation)
      ├── Indie Hackers (manual copy-paste, founder angle)
      ├── Substack (manual copy-paste, newsletter format)
      └── Medium (manual import via URL, uses CPM site URL)
```

**Why this matters for SEO:** Every platform post links back to `cpm.yourdomain.com`. Google sees the CPM site as the original source. Dev.to and Hashnode both support canonical URL fields that explicitly tell search engines "the real article is over there." You get the community reach of all platforms without splitting your SEO authority.

**Why this matters for CPM:** CPM generates one master article. Then CPM generates a platform-adapted version for each channel — different tone, different length, different hook — but sourced from the same master. This is the content pipeline Claude Code builds.

## The Dogfooding Principle Applied to Marketing

CPM markets CPM. This is not a side effect — it is the strategy.

Every CPM launch campaign is itself proof that CPM works. The content generated for CPM's own launch becomes the most credible case study CPM has. When a founder reads a CPM article on Hacker News describing how CPM built and launched a product overnight, and that article was itself generated by CPM's Stage 7 pipeline — the product sells itself.

This means CPM's content generator must always be aware it is generating content about CPM. The GOAL of every Stage 7 content run for CPM itself is: **demonstrate the capability by demonstrating the capability.**

## The CPM Content Generation Spec

When Claude Code implements `@cpm/social`, the content generator must produce the following outputs from a single master article input. Each output is stored in Supabase table `generated_content` with a `platform` field and a `status` of `ready_for_review`.

### Input: Master Article
Fields required from CPM Stage 7:
- `title` — full article title
- `body_markdown` — full article in Markdown
- `summary` — 2–3 sentence summary
- `target_audience` — e.g. "indie hackers, solo founders, AI developers"
- `product_name` — e.g. "CPM — CodePromptMaker"
- `product_url` — canonical product URL
- `canonical_url` — CPM website article URL (e.g. `https://cpm.yourdomain.com/blog/article-slug`)
- `tags` — array of relevant tags

### Output per Platform

**CPM Website (master publish)**
Full article in Markdown published to CPM blog. Generates canonical URL used by all other platforms. SEO meta: title, description, OG image, keywords.

**Dev.to**
Full article body (Markdown, identical or lightly adapted). Front matter includes `canonical_url` pointing to CPM site. Tone: technical, peer-to-peer, slightly informal. Call to action at bottom links to CPM website.

**Hashnode**
Full article body (Markdown). `originalArticleURL` set to CPM site canonical. Publication mapped to CPM's own domain via Headless Hashnode for maximum SEO benefit.

**LinkedIn (Personal)**
1,200–1,500 characters (algorithm sweet spot). Hook in first line — no "I" as first word (LinkedIn penalises it). 3–5 short paragraphs with line breaks. 3–5 hashtags at end. Link to article in first comment, not post body (better reach).

**LinkedIn (Company — WebHouse ApS)**
800–1,000 characters. More formal. Focus on product value for customers. Hashtags: `#AITools #SaaS #ProductDevelopment #DevTools`.

**Instagram**
Caption: 150–200 words max. Hook in first line only (rest hidden behind "more"). 10–15 hashtags. Ends with "Link in bio →". Also generate `media_prompt` field describing the visual card layout for image generation.

**Product Hunt (launch day only)**
- `name`: product name (max 60 chars)
- `tagline`: one-line hook (max 60 chars, no exclamation marks — PH penalises them)
- `description`: 200–300 words, benefit-focused, no buzzwords
- First comment draft: maker story, problem solved, invitation for questions

**Hacker News Show HN (manual — copy-paste ready)**
3 alternative titles (max 80 chars each, no marketing language). Opening comment: 150–250 words, technical, honest about limitations, invites feedback. Tone: hacker-to-hacker, zero spin.

**Reddit (manual — copy-paste ready, per subreddit)**
One version per subreddit: `r/SaaS`, `r/ClaudeAI`, `r/webdev`, `r/indiehackers`, `r/node`. Each leads with value before mentioning the product. Title never reads as advertising.

**Indie Hackers (manual — copy-paste ready)**
400–600 words. Structure: Problem → Attempt → Failure → Insight → Solution → Current Status → Numbers. Radically honest, includes what went wrong. Ends with a question to the community.

**Substack (manual — copy-paste ready)**
3 alternative subject lines. Preview text (100 chars). Full newsletter issue: personal intro + adapted article + what's next + CTA. Tone: email from a friend, not a blog post. 600–900 words.

**Medium (manual — import via URL)**
No content generation needed. CPM generates an import reminder task with the canonical CPM site URL pre-filled. Status tracked as `import_pending`. After manual import: status updated to `published_manual`.

## Supabase Schema for `@cpm/social`

```sql
-- Stores OAuth credentials per platform per project
CREATE TABLE platform_credentials (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
  platform TEXT NOT NULL,
  access_token TEXT NOT NULL,
  refresh_token TEXT,
  token_expires_at TIMESTAMPTZ,
  metadata JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Master content pieces (one per article/campaign)
CREATE TABLE content_pieces (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  body_markdown TEXT NOT NULL,
  summary TEXT,
  canonical_url TEXT,
  target_audience TEXT,
  tags TEXT[],
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Per-platform generated content (one row per platform per content piece)
CREATE TABLE generated_content (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  content_piece_id UUID REFERENCES content_pieces(id) ON DELETE CASCADE,
  platform TEXT NOT NULL,
  generated_body TEXT NOT NULL,
  media_prompt TEXT,
  metadata JSONB,
  status TEXT DEFAULT 'ready_for_review',
  -- ready_for_review | approved | scheduled | publishing | published | failed | import_pending | published_manual
  approved_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Scheduled posts queue
CREATE TABLE scheduled_posts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  generated_content_id UUID REFERENCES generated_content(id),
  project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
  platform TEXT NOT NULL,
  scheduled_at TIMESTAMPTZ NOT NULL,
  status TEXT DEFAULT 'pending',
  -- pending | publishing | published | failed | skipped
  platform_post_id TEXT,
  platform_post_url TEXT,
  error_message TEXT,
  retry_count INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Execution log
CREATE TABLE post_execution_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  scheduled_post_id UUID REFERENCES scheduled_posts(id),
  executed_at TIMESTAMPTZ DEFAULT NOW(),
  http_status INTEGER,
  request_payload JSONB,
  response_payload JSONB,
  duration_ms INTEGER
);
```

### Platform A: LinkedIn

#### What You Can Post
- Text updates to personal profile
- Text + image updates to WebHouse ApS Company Page
- Recommended maximum: 1 post per day per profile

#### What You Cannot Post via API
- LinkedIn newsletters, documents, PDFs, polls, Stories

#### Step 1 — Create WebHouse ApS Company Page (if not exists)
`linkedin.com` → Work (grid icon) → Create a Company Page → Company → fill details + logo → Create Page

#### Step 2 — Create LinkedIn Developer App
`developer.linkedin.com` → Create App → name: `CPM Social Publisher` → select WebHouse ApS page → add logo → accept legal agreement → Create app

#### Step 3 — Add API Products (Products tab)
Request access to:
- **Sign In with LinkedIn using OpenID Connect**
- **Share on LinkedIn**
- **Community Management API** ← requires WebHouse ApS as legal entity (it qualifies)

Community Management API tiers:
- **Development** — auto-granted, call limits, valid 12 months
- **Standard** — apply separately for production volume

#### Step 4 — Community Management App Review
After requesting Community Management API, LinkedIn sends a review form.

Use case description: *"Automated publishing of product launch and educational content to our WebHouse ApS company page as part of our AI-assisted product development platform."*

Wait **3–7 business days**. Monitor the Products tab for approval status.

> ⚠️ Start this on Day 1 — it is the longest step in the entire setup.

#### Step 5 — Configure OAuth Redirect URI
App dashboard → Auth tab → Add redirect URIs:
- Production: `https://your-cpm.fly.dev/oauth/linkedin/callback`
- Local: `http://localhost:3000/oauth/linkedin/callback`

Copy and store Client ID and Client Secret.

#### Step 6 — OAuth Scopes
Personal profile: `openid profile email w_member_social`

Company Page (requires Community Management API approval):
`openid profile email w_member_social r_organization_social w_organization_social rw_organization_admin`

#### Step 7 — Get Organization URN
After authenticating:
```
GET https://api.linkedin.com/v2/organizationalEntityAcls?q=roleAssignee
```
Returns `urn:li:organization:XXXXXXXX` — save to `platform_credentials.metadata`.

#### Step 8 — Token Lifecycle
- Access tokens expire after **60 days**
- Refresh tokens valid for **12 months**
- Store both in `platform_credentials`
- CPM alerts when token expires within 7 days

#### API Version
Always include header: `LinkedIn-Version: 202504`
Do NOT use deprecated `ugcPost` endpoint. Use `/v2/posts`.

#### Credentials for `.env`
```
LINKEDIN_CLIENT_ID=
LINKEDIN_CLIENT_SECRET=
LINKEDIN_REDIRECT_URI=
LINKEDIN_ORG_URN=urn:li:organization:XXXXXXXX
LINKEDIN_ACCESS_TOKEN=
LINKEDIN_REFRESH_TOKEN=
```

### Platform B: Instagram

#### What You Can Post
- Single images (JPEG only, min 600px, recommended 1080×1080px)
- Carousels (multiple images, counts as 1 post)
- Reels (video)
- Maximum **25 posts per 24 hours**

#### What You Cannot Post via API
- Stories, Instagram Live, shopping tags, filters

#### Step 1 — Convert to Instagram Business Account
Instagram app → Profile → ≡ → Settings and privacy → Account type and tools → Switch to professional account → Business → connect to Facebook Page

#### Step 2 — Create Facebook Page
`facebook.com/pages/create` → Business or brand → name: `WebHouse ApS` → add logo → Publish

#### Step 3 — Link Instagram to Facebook Page
Facebook Page Settings → Linked accounts → Instagram → Connect

#### Step 4 — Create Meta Developer App
`developers.facebook.com` → My Apps → Create App → use case: Other → type: Business → name: `CPM Social Publisher` → connect Business Portfolio

#### Step 5 — Add Instagram Product and Request Permissions
App dashboard → Add Product → Instagram → Set up

Request:
- `instagram_basic`
- `instagram_content_publish`
- `pages_read_engagement`

> App Review required for production (1–5 business days). During development, test with accounts listed as Test Users in your app.

#### Step 6 — Get Long-Lived Page Access Token (never expires)

Step 6a — Short-lived token via Graph API Explorer at `developers.facebook.com/tools/explorer`

Step 6b — Exchange for long-lived (60 days):
```
GET https://graph.facebook.com/v22.0/oauth/access_token
  ?grant_type=fb_exchange_token
  &client_id={APP_ID}
  &client_secret={APP_SECRET}
  &fb_exchange_token={SHORT_LIVED_TOKEN}
```

Step 6c — Get Page Access Token (never expires):
```
GET https://graph.facebook.com/v22.0/me/accounts
  ?access_token={LONG_LIVED_USER_TOKEN}
```
Save the Page Access Token from the response.

#### Step 7 — Get Instagram Business Account ID
```
GET https://graph.facebook.com/v22.0/{PAGE_ID}
  ?fields=instagram_business_account
  &access_token={PAGE_ACCESS_TOKEN}
```
Save `instagram_business_account.id` to `platform_credentials.metadata`.

#### Step 8 — The Two-Step Posting Flow

Step A — Create media container:
```
POST https://graph.facebook.com/v22.0/{IG_BUSINESS_ACCOUNT_ID}/media
  image_url={PUBLIC_HTTPS_IMAGE_URL}
  caption={POST_CAPTION}
  access_token={PAGE_ACCESS_TOKEN}
```
Returns `container_id`.

Poll container status until `STATUS_CODE = FINISHED`:
```
GET https://graph.facebook.com/v22.0/{CONTAINER_ID}
  ?fields=status_code
  &access_token={PAGE_ACCESS_TOKEN}
```

Step B — Publish:
```
POST https://graph.facebook.com/v22.0/{IG_BUSINESS_ACCOUNT_ID}/media_publish
  creation_id={CONTAINER_ID}
  access_token={PAGE_ACCESS_TOKEN}
```

> Images must be uploaded to Supabase Storage or Cloudflare R2 and served via public HTTPS before posting.
> Use API version `v22.0` or latest stable.
> Base URL: `https://graph.facebook.com/` — NOT `graph.instagram.com`

#### Credentials for `.env`
```
META_APP_ID=
META_APP_SECRET=
META_PAGE_ID=
META_PAGE_ACCESS_TOKEN=
INSTAGRAM_BUSINESS_ACCOUNT_ID=
```

### Platform E: Hashnode

#### What You Can Post
- Full technical articles (Markdown)
- With canonical URL back to CPM site
- Optionally mapped to your own domain via Headless Hashnode

#### Why Headless Hashnode
Hashnode lets you map a publication to your own domain (e.g. `blog.cpm.yourdomain.com`). Posts appear as your domain in Google — even stronger SEO than a canonical URL alone. Set this up in Hashnode publication settings.

#### Step 1 — Create Hashnode Publication
`hashnode.com` → Create → Publication → set name, slug, connect custom domain if desired

#### Step 2 — Get Personal Access Token
`hashnode.com` → Profile picture → Account Settings → Developer → Generate New Token → name: `CPM Social Publisher`. Copy token.

#### Step 3 — Get Publication ID
```graphql
# POST https://gql.hashnode.com
# Authorization: {YOUR_TOKEN}

query {
  me {
    publications(first: 10) {
      edges {
        node { id title url }
      }
    }
  }
}
```
Save the publication `id`.

#### Step 4 — Publish Article (draft)
```graphql
mutation PublishPost($input: PublishPostInput!) {
  publishPost(input: $input) {
    post { id title url slug }
  }
}
```

Variables:
```json
{
  "input": {
    "title": "Article Title",
    "contentMarkdown": "Full article body...",
    "publicationId": "YOUR_PUBLICATION_ID",
    "tags": [{ "slug": "ai" }, { "slug": "nodejs" }],
    "originalArticleURL": "https://cpm.yourdomain.com/blog/article-slug",
    "metaTags": {
      "title": "SEO Title",
      "description": "SEO description"
    }
  }
}
```

> `originalArticleURL` sets canonical URL automatically. Always create as draft — review before publishing.

#### Credentials for `.env`
```
HASHNODE_ACCESS_TOKEN=
HASHNODE_PUBLICATION_ID=
```

## Platform API Setup: Tier 2 (Manual — CPM Generates, Human Pastes)

For all Tier 2 platforms, `@cpm/social` generates ready-to-paste content stored in Supabase with status `ready_for_manual_publish`. CPM dashboard displays each with a **Copy** button and a direct link to the platform's post editor.

---

### Hacker News

No API. Strict community. Pure value — no spin.

**CPM generates:**
- 3 alternative Show HN titles (max 80 chars, no marketing language)
- Opening comment: 150–250 words, technical, honest, invites questions
- Best posting window: Tuesday–Thursday, 08:00–10:00 UTC
- Worst posting window: Friday 18:00 – Monday 09:00 UTC (avoid)

**Human action:**
1. `news.ycombinator.com/submit`
2. URL: CPM site article URL
3. Title: pick from 3 alternatives
4. Submit
5. Immediately post generated opening comment as first comment on your own submission

---

### Reddit

Posting API exists but automation violates Reddit's terms of service for self-promotion. Manual only. Post to **one subreddit per day** — simultaneous posting triggers spam filters.

**CPM generates one adapted post per subreddit:**
- `r/SaaS` — founder angle, revenue/traction focus
- `r/ClaudeAI` — technical Claude Code integration angle
- `r/webdev` — stack choices, technical architecture
- `r/indiehackers` — solo founder story, build-in-public
- `r/node` — Node.js technical implementation

Each post leads with value before any product mention. Title never reads as advertising.

**Human action:** CPM dashboard shows each version with Copy button + subreddit link. Paste, review, adjust tone if needed, submit.

---

### Indie Hackers

No API. The best possible Ideal Customer Profile (ICP) for CPM: founders building products with AI, sharing revenue, looking for tools.

**CPM generates:**
- Milestone post or "how I built this" (400–600 words)
- Radically honest — includes what went wrong
- Ends with a genuine question to the community (drives comments)
- Links to CPM website naturally within narrative

**Human action:** Paste into `indiehackers.com/post`. Add 1–2 sentences in your own voice before submitting.

---

### Substack

No API. Long-term email list is the most valuable marketing asset CPM builds over time. Start now even with 0 subscribers.

**One-time setup:** Create publication at `substack.com`. Recommended name: `The Overnight Product` or similar. Connect custom domain when ready.

**CPM generates per issue:**
- 3 alternative subject lines
- Preview text (100 chars max)
- Full newsletter: personal intro (3 sentences) + adapted article + "what I'm building next" section + CTA
- Tone: email from a friend, not a blog post
- Length target: 600–900 words

**Human action:** Paste into Substack editor, personalise if desired, schedule or send.

---

### Medium

API closed to new users. Uses hub-and-spoke import workaround.

**Check first:** `medium.com/me/settings/security` → Integration tokens. If any token exists → Medium becomes Tier 1. Update `.env` with `MEDIUM_INTEGRATION_TOKEN` and `MEDIUM_USER_ID`.

**If no token (import workaround):**

## What Claude Code Should Build

Target: `packages/social/` in the CPM monorepo.

```
packages/social/
  src/
    platforms/
      linkedin.js          — LinkedIn REST API (personal + company)
      instagram.js         — Meta Graph API (two-step container flow)
      producthunt.js       — Product Hunt GraphQL
      devto.js             — Dev.to REST API
      hashnode.js          — Hashnode GraphQL
      medium.js            — Medium API (conditional on token)
    content/
      generator.js         — Master → per-platform content adaptation
      templates/
        linkedin-personal.md
        linkedin-company.md
        instagram.md
        producthunt.md
        devto.md
        hashnode.md
        hackernews.md
        reddit-saas.md
        reddit-claudeai.md
        reddit-webdev.md
        reddit-indiehackers.md
        reddit-node.md
        indiehackers.md
        substack.md
    scheduler/
      poster.js            — Main dispatcher
      queue.js             — BullMQ or 60-second polling
    storage/
      credentials.js       — Supabase credential store + token lifecycle
      media.js             — Upload images to Supabase Storage → public URL
    index.js
```

**GOAL:** Implement `@cpm/social` as a complete ESM Node.js package that generates platform-adapted content from a master article, stores all output in Supabase for human review, publishes approved Tier 1 content on schedule, and surfaces Tier 2 manual content via the CPM dashboard.

**CONSTRAINTS:**
- All secrets via DotEnv — never hardcoded
- All platform clients expose a uniform `publish(post): Promise<{success, platformPostId, platformPostUrl}>` interface
- Retry logic with exponential backoff on all API calls (max 3 retries, except token errors which do not retry)
- Instagram: poll container status before publishing — do not use fixed waits
- LinkedIn: always include `LinkedIn-Version: 202504` header
- Dev.to and Hashnode: always `published: false` — human publishes via platform dashboard
- Product Hunt: always create as pending post — human confirms before going live
- All Tier 2 content stored as `ready_for_manual_publish` — never auto-posted
- Media images uploaded to Supabase Storage before any platform posting call

**FAILURE CONDITIONS:**
- LinkedIn token expired → `status: failed`, error: `LINKEDIN_TOKEN_EXPIRED`, no retry, dashboard alert
- Instagram container `ERROR` after 3 polls → `status: failed`, no publish
- Product Hunt `unauthorized_oauth` → `status: failed`, no retry
- HTTP 429 → requeue with 1-hour delay, increment `retry_count`
- HTTP 5xx → retry with exponential backoff, max 3 attempts
- Missing credential for platform → `status: failed`, error: `CREDENTIAL_MISSING`, dashboard alert
