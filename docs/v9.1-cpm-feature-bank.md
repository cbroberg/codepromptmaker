# v9.1 — CPM Feature Bank: Fra Apple Notes til AI-drevet Feature Management

> **Version:** v9.1
> **Afhængigheder:** v9 (Project Onboarding), v5.0 (Plan Management, Connector Architecture), v6 (Interview Module)
> **Formål:** Erstat Apple Notes som feature tracker med en struktureret Feature Bank der kan klassificere, validere, prioritere og omdanne features til Prompt Contracts.

---

## 1. Problemet

Christian vedligeholder i dag en Apple Notes-note med features til FysioDK Sport. Listen er ustruktureret, blander store og små opgaver, og har ingen forbindelse til kodebasen. Eksempler fra den faktiske liste:

| Feature-note | Type | Kompleksitet | Berører |
|---|---|---|---|
| "Chat mellem træner og patient og fys på sagen" | Ny funktionalitet | Stor (real-time, DB, UI) | profiles, injuries, nyt chat-system |
| "Admin skal kunne rette klub på bruger" | UI fix/udvidelse | Lille | profiles admin, UI |
| "Multi tenant support (videresalg til Brønderslev)" | Arkitekturel | Kæmpestor | Alt (DB, RLS, auth, deploy) |
| "Fotos af skaden i wizard" | Ny funktionalitet | Medium | injuries wizard, storage buckets |
| "Vi skal have nye screenshots til iPhone" | Operations/marketing | Lille | Intet kode |
| "Unit tests" | Infrastruktur | Stor | Test framework setup |
| "Snak med vores AI sundheds Bot (RAG)" | Ny funktionalitet | Stor | RAG pipeline, ny UI |

**Problemerne:**
- Ingen prioritering ud over rækkefølge i noten
- Ingen viden om hvad der er realistisk givet nuværende kodebase
- Ingen estimering af scope eller afhængigheder
- Features kan ikke omdannes til cc-opgaver direkte
- Duplikater og overlappende features er svære at spotte
- Ingen link til commits, planer eller sessioner

## 2. Feature Bank Konceptet

Feature Bank er CPM's svar på en intelligent backlog der forstår koden bag.

### Kerneegenskaber

1. **Capture** — Hurtigt input af features i naturligt sprog (som Apple Notes, men struktureret)
2. **Classify** — Automatisk klassificering: type, størrelse, berørte systemer
3. **Validate** — Kodebase-informeret realitetstjek: "Er dette muligt med nuværende schema?"
4. **Prioritize** — Effort/impact matrix med forslag baseret på afhængigheder
5. **Plan** — Omdannelse af feature til Plan → Prompt Contract(s)
6. **Track** — Lifecycle tracking: idea → planned → in-progress → shipped → verified

## 3. Feature Data Model

```typescript
interface Feature {
  id: string;                          // UUID
  projectId: string;                   // Link til Project DNA
  
  // Input (brugerens egne ord)
  title: string;                       // Kort titel
  description: string;                 // Fritekst beskrivelse (markdown)
  source: 'manual' | 'import' | 'interview' | 'ai-suggested';
  sourceRef: string | null;            // Apple Notes import ID, interview session, etc.
  
  // Klassificering (auto + manuel override)
  classification: {
    type: FeatureType;
    size: FeatureSize;
    category: FeatureCategory;
    affectedSystems: string[];         // ["database", "api", "ui", "mobile", "deploy"]
    affectedTables: string[];          // ["profiles", "clinics"] — fra Project DNA
    affectedFiles: string[];           // Estimerede filer der skal ændres
    requiresNewDependency: boolean;
    requiresMigration: boolean;
    requiresNativeBuild: boolean;      // iOS/Android rebuild
    breakingChange: boolean;
  };
  
  // Validering mod kodebase
  validation: {
    status: 'pending' | 'validated' | 'conflict' | 'needs-clarification';
    feasibilityScore: number;          // 1-10
    notes: string[];                   // "Profiles-tabellen har ikke tenant_id"
    prerequisites: string[];           // "Kræver klubber-entity først"
    risks: string[];                   // "Bryder eksisterende RLS policies"
    relatedFeatures: string[];         // Feature IDs der overlapper
    validatedAt: Date | null;
    validatedAgainstCommit: string | null;  // Git SHA
  };
  
  // Prioritering
  priority: {
    effort: 'xs' | 's' | 'm' | 'l' | 'xl';
    impact: 'low' | 'medium' | 'high' | 'critical';
    urgency: 'backlog' | 'next' | 'now' | 'blocked';
    score: number | null;              // Beregnet effort/impact score
    dependencies: string[];            // Feature IDs der skal bygges først
    blockedBy: string[];               // Feature IDs der blokerer denne
  };
  
  // Lifecycle
  status: FeatureStatus;
  linkedPlanIds: string[];             // Planer genereret fra denne feature
  linkedPromptIds: string[];           // Prompt Contracts genereret
  linkedSessionIds: string[];          // cc sessions der implementerede featuren
  linkedCommits: string[];             // Git commits der løser featuren
  
  // Meta
  tags: string[];
  assignee: string | null;            // Teammedlem
  createdAt: Date;
  updatedAt: Date;
  shippedAt: Date | null;
}

type FeatureType = 
  | 'new-feature'        // Ny funktionalitet
  | 'enhancement'        // Forbedring af eksisterende
  | 'bugfix'             // Fejlrettelse
  | 'infrastructure'     // Test, CI/CD, performance
  | 'architecture'       // Større arkitekturel ændring
  | 'operations'         // Marketing, screenshots, emails
  | 'research'           // Undersøgelse, evaluering
  | 'communication';     // Emails, briefings til stakeholders

type FeatureSize = 'tiny' | 'small' | 'medium' | 'large' | 'epic';

type FeatureCategory =
  | 'user-facing'        // Brugere kan se/mærke det
  | 'admin'              // Kun admin/behandlere
  | 'developer'          // Developer tools, tests
  | 'business'           // Salg, marketing, pricing
  | 'security'           // Auth, permissions, GDPR
  | 'mobile-native';     // Platform-specifikt (iOS/Android)

type FeatureStatus = 
  | 'idea'               // Lige fanget
  | 'classified'         // Auto-klassificeret
  | 'validated'          // Valideret mod kodebase
  | 'planned'            // Plan oprettet
  | 'prompted'           // Prompt Contract(s) genereret
  | 'in-progress'        // cc arbejder på det
  | 'review'             // Kode klar til review
  | 'shipped'            // Deployet
  | 'verified';          // E2E testet og bekræftet
```

## 5. Feature Bank Workflows

### 5.1 Quick Capture (erstatter Apple Notes)

```bash
# Hurtigt input — som at skrive i Apple Notes
cpm feature add "Chat mellem træner og patient"
cpm feature add "Admin skal kunne rette klub" --tag admin --size small
cpm feature add "Multi tenant support" --type architecture --size epic

# Bulk import fra fil (f.eks. eksisterende Apple Notes export)
cpm feature import features.txt --project fysiodk-sport

# Import fra Apple Notes direkte (via connector)
cpm feature import --apple-notes "FDS Features"
```

### 5.2 Auto-Klassificering

Når en feature tilføjes, kører CPM automatisk:

1. **Type detection** — Parser naturligt sprog og gætter type
2. **Size estimation** — Baseret på nøgleord og erfaringsdata
3. **System mapping** — Matcher feature-beskrivelse mod Project DNA's tabeller, routes og komponenter
4. **Dependency detection** — Finder andre features der bør bygges først

```
$ cpm feature add "Klubber som ny entity med ægte join fra profil"

✅ Feature F5 oprettet: "Klubber som ny entity"
   Type: new-feature (auto)
   Size: medium (auto — ny tabel + UI + migration)
   Berører: database (ny tabel), profiles (FK), admin UI
   Kræver migration: Ja
   Kræver native build: Nej
   Mulig dependency for: F3 (admin retter klub), F4 (multi-tenant)
```

### 5.3 Kodebase-Validering

```bash
cpm feature validate F5
```

CPM analyserer Project DNA og kodebasen:

```
Validering af F5: "Klubber som ny entity"

📊 Feasibility Score: 8/10

✅ Kompatibelt:
   - profiles-tabellen kan udvides med club_id FK
   - Admin UI patterns eksisterer (clinics CRUD er reference-implementation)
   - RLS policies følger samme pattern som clinics

⚠️ Opmærksomheder:
   - Signup-flow viser fritekst-felt i dag — behold som legacy
   - constants.ts role-permissions skal opdateres
   - 3 E2E flows berøres (signup, injury, coach notification)

🔗 Relaterede features:
   - F3 (admin retter klub) — kan bygges SOM DEL AF F5
   - F4 (multi-tenant) — F5 er naturligt fundament

📁 Estimerede fil-ændringer:
   - supabase/migrations/00015_clubs.sql (ny)
   - packages/shared/src/types.ts (udvidet)
   - apps/web/src/app/(app)/app/admin/clubs/ (ny route group)
   - apps/web/src/components/forms/register-form.tsx (udvidet)
   - apps/web/src/app/(app)/app/admin/users/[id]/ (klub-selector)
   - tests/e2e/01-signup-confirm.spec.js (opdatér)
```

### 5.4 Feature → Plan → Prompt Contract Pipeline

```bash
# Generér plan fra feature
cpm feature plan F5

# Genererer:
# 1. En Plan (v5 Plan Management) med implementeringstrin
# 2. N Prompt Contracts slicet efter CPM's Section Splitting
# 3. Hvert Prompt Contract præfyldt med Project DNA context

# Direkte execution
cpm feature build F5              # Plan → Prompt Contracts → cc runner
cpm feature build F5 --dry-run    # Vis hvad der ville ske
```

## 6. Apple Notes Connector

For at gøre overgangen smooth, kan CPM importere direkte fra Apple Notes:

```typescript
interface AppleNotesConnector {
  id: 'apple-notes';
  name: 'Apple Notes';
  category: 'capture';
  
  // macOS only — bruger AppleScript/Shortcuts
  methods: {
    listNotes(): NoteReference[];
    getNoteContent(id: string): string;
    watchNote(id: string, callback: (content: string) => void): void;
  };
}
```

**Workflow:** "Synkroniser min Apple Notes-liste med Feature Bank" → CPM parser noten, opretter features, og holder dem synkroniseret. Over tid migrerer brugeren naturligt til Feature Bank direkte, fordi den tilføjer validering, prioritering og planning som Apple Notes ikke kan.

### Hvorfor v9 og ikke v5.x?

Feature Bank og Project Onboarding er *ikke bare udvidelser* af v5. De repræsenterer en fundamental ny capability — CPM som **App Manager** snarere end blot en prompt generator. Det fortjener sin egen version for at signalere:

- Ny persona: CPM er nu manager for levende apps, ikke bare et development tool
- Ny pipeline: Feature → Validate → Plan → Contract → Build → Ship → Verify
- Ny datakilde: GitHub repos, database schemas, CLAUDE.md filer
- Ny integration: Apple Notes, GitHub Issues, potentielt Linear/Jira

## 8. Dogfooding: CPM Feature Bank for CPM

Per CPM's dogfooding-princip: CPM's egen roadmap (v1-v9.1) bør selv leve i Feature Bank:

```bash
cpm project import --github webhousecode/codepromptmaker
cpm feature add "Plan Management v5.0" --type architecture --size large
cpm feature add "Knowledge Extractor v8" --type new-feature --size large
cpm feature add "Feature Bank v9.1" --type new-feature --size epic
cpm feature validate "Feature Bank v9.1"
```

CPM bygger Feature Bank ved hjælp af sin egen Plan Management. Plan Management er bygget via Prompt Contracts. Prompt Contracts er CPM's kerneprodukt. Cirklen er komplet.

## 10. Opsummering

Feature Bank løser det konkrete problem at Christians Apple Notes-liste med FDS features lever i et vacuum uden forbindelse til koden den skal ændre. Ved at give features et hjem i CPM med automatisk klassificering, kodebase-validering og direkte pipeline til Prompt Contracts, transformerer vi en passiv todo-liste til en aktiv build pipeline.

Det er forskellen mellem:
- **Apple Notes:** "Chat mellem træner og patient" → ??? → måske en dag
- **CPM Feature Bank:** "Chat mellem træner og patient" → klassificeret (real-time feature, large, Supabase Realtime) → valideret (muligt, kræver 2 nye tabeller, 5 berørte filer) → planlagt → 3 Prompt Contracts genereret → cc bygger det natten over

Fra ide til deployet feature — med CPM som manager hele vejen.
